# CRM Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `AbdulSubhan1/crm-kit`, a Claude Code plugin made of skills plus a business-free starter codebase extracted from PolicyDesk, so that one request ("use the CRM kit, build a CRM for X") creates a new CRM built to PolicyDesk's standard.

**Architecture:**

- **Skills** (`skills/*/SKILL.md`) hold the process: start, components, business knowledge base, standard, build, test, sync-back.
- **`template/`** is a working Next.js app: PolicyDesk with all insurance code removed.
- **Node scripts** (`scripts/*.mjs`) do the mechanical parts (create a project, apply market settings, sync back, self-check), so skills say "run this" instead of re-typing code.
- **`references/`** holds long guidance and the module pattern the skills point to.

**Tech Stack:** Claude Code plugin format (`.claude-plugin/plugin.json`, `marketplace.json`, `skills/<name>/SKILL.md` with `name`/`description` frontmatter); Node 22 ESM scripts tested with `node --test`. The template uses PolicyDesk's stack unchanged.

**Spec:** `docs/superpowers/specs/2026-11-11-crm-kit-design.md` (this repo, branch `docs/crm-kit-design`).

## Global Constraints

- Personal accounts only: GitHub `AbdulSubhan1`, the owner's personal Vercel. No company code, names or assets anywhere in the kit.
- The template stack is PolicyDesk's, at its current versions: `next` 15.5.29, `react`/`react-dom` 19.1.10, next-intl 4.14.10, Drizzle, Tailwind CSS 4, RHF + Zod, Playwright 1.52+.
- No UI or styling libraries (MUI, Radix, shadcn, lucide, clsx, tailwind-merge). The ESLint rules from PolicyDesk ship unchanged.
- The template contains **no business logic**:
  - only the Admin role, plus the platform permissions `dashboard:view`, `users:manage`, `roles:manage`, `audit:view`;
  - no business module, no dashboard tiles, no business nav items.
- The six start questions are exactly: industry, app name, country, languages, currency, brand colour. Each has a suggestion when unanswered; the industry must come from the owner.
- Every kit question uses the four-part format: what the research found (with source), why it asks, what each answer does (with example), the recommendation.
- Each process step stops for the owner's "go". Creating a GitHub repo or Vercel project always asks first.
- E2E runs on demand: targeted specs during work, the full suite once at the end.
- PolicyDesk itself is not modified by this plan, apart from the plan and spec files.

## Review Focus

1. **Business words left in the template** (lead, policy, quote, KYC, insurance, PolicyDesk, `pd_` cookie names) → `check-kit` fails, naming the file and line. Test in Task 6.
2. **Creating into a folder that already exists or isn't empty** → `create.mjs` refuses with a clear message and changes nothing. Test in Task 4.
3. **A second language that isn't Arabic** (Urdu, or a left-to-right one like French) → `configure.mjs` writes the locale list, marks Urdu as RTL and French as LTR, copies `en.json` as the starting messages for the new locale, and the app still builds. Test in Task 4.
4. **`sync-back` given a file containing business words, or a path outside the CRM** → refuses that file, copies the rest, and reports which were skipped. Test in Task 5.
5. **A skill pointing at a script or reference that doesn't exist** → `check-kit` fails. Test in Task 6.

## File Structure (new repo `~/crm-kit`)

```
.claude-plugin/plugin.json        name "crm-kit", version "0.1.0", author AbdulSubhan1
.claude-plugin/marketplace.json   one plugin, source "./"
README.md  CHANGELOG.md  LICENSE (MIT)  .gitignore  package.json (scripts: test, check)
scripts/
  create.mjs        createProject(dest, answers) → copies template/, runs configure, git init
  configure.mjs     configureProject(dir, answers) → market settings
  sync-back.mjs     syncBack({ crmDir, kitDir, files, bump, note }) → copies generic files into template/
  check-kit.mjs     checkKit(kitDir) → returns a list of problems; CLI exits 1 if any
  lib/answers.mjs   validateAnswers(answers), suggestDefaults(partial)
  *.test.mjs        node:test tests for each script
template/           the business-free app (Tasks 1–3)
references/
  module-pattern/   one complete module ("contacts") + MAP.md (file → destination)
  component-research.md  component-checklist.md  kb-format.md
  question-format.md     standards-sources.md     market-defaults.md
skills/
  new-crm/  research-components/  research-business/  standards/
  build-module/  test/  sync-back/        (each SKILL.md)
```

`answers` shape (used by every script and skill):

```ts
type Answers = {
  industry: string; // "gym"
  appName: string; // "FitDesk"
  slug: string; // "fitdesk", folder and package name, [a-z0-9-]+
  country: string; // ISO 3166-1 alpha-2, "PK"
  locales: string[]; // first is "en", e.g. ["en", "ur"]
  currency: string; // ISO 4217, "PKR"
  brand: { base: string; strong: string; soft: string }; // hex, e.g. "#0f766e", "#115e59", "#ccfbf1"
};
```
